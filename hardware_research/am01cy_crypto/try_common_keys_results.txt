non-decrypts. Top composite scorers were false positives: a lone 32-bit word that happens
to look like a 0x0800_xxxx reset vector, plus base-rate printable bytes -- never a real SP.

--------------------------------------------------------------------------------
INNER-CIPHER CHARACTERIZATION (structural)  -- reframes the problem
--------------------------------------------------------------------------------
1. Descramble transform confirmed correct: among taps {shl1, rotl1, shr1, rotr1, shl2,
   shl1^shr7, identity} x const {0,0x21,0xff}, plain shl1 uniquely MINIMIZES entropy on the
   structured window 0xe4000 (ent 6.510). So the outer layer is genuinely shl1.

2. Descrambling reveals REAL low-entropy structured data -- impossible under a strong cipher:
   - 4KB-window entropy of ds: 213/251 windows ~8.0, but 15 windows < 7.0, clustered in
     0x7f000..0xfb000; the 512B window at 0xe4c00 has entropy 1.508 (bytes are ~all 0x00/0x21).
   - A uniform AES-* layer over the payload would give ~8.0 in every window. It does not.

3. RAW ciphertext (before descramble) autocorrelation P(c[i]==c[i+p]), N=400k, baseline 1/256=0.00391:
     p=16 -> 0.0038 (flat)   p=32 -> 0.0113 (SPIKE)   p=64 -> 0.0107 (SPIKE)   all other p ~0.0039
   Bulk 0x0..0x7e000:  p16=0.0039  p32=0.0117  p64=0.0109
   Tail 0x7f000..0xfb000: p16=0.0038 p32=0.0182 p64=0.0170
   => uniform period-32 structure across the WHOLE image; flat at 16 and non-multiples of 32.

4. Methodology control (same measurement on known ciphers):
     os.urandom:      p16=0.00402 p32=0.00401 p64=0.00411  (flat)
     AES-CTR(zeros):  p16=0.00402 p32=0.00398 p64=0.00391  (flat)  <-- a strong cipher is FLAT
     AES-ECB(32B-periodic pt): p=1.0 (as expected)
   The target's p32=0.0113 is ~65 sigma above baseline and above real AES-CTR. A correctly
   implemented strong stream/CBC/CTR cipher CANNOT produce this. => payload is NOT AES-*-protected
   in a standard mode; ECB-16 is also excluded (would spike at p=16, which is flat).

5. But it is NOT a trivial repeating-key cipher either: period-32 single-byte column attack
   (key = per-column mode, XOR and additive) FAILS -- RAW stays entropy 7.997, minWin 7.71.
   So plaintext columns are not 0x00-dominant; the 32-byte structure is subtler than Vigenere.

6. ECB block-collision test on ds: 8B blocks 639 dup-collisions, 16B blocks 5, 32B 1
   (random expectation ~0). Elevated but localized to the low-entropy tail records.

INTERPRETATION: The "inner strong AES-class cipher, key on-chip" hypothesis is contradicted.
The scheme is a lightweight, position-preserving, 32-byte-periodic transform (descramble +
an unsolved 32-byte-period element) over a payload that is part high-entropy (compressed or
packed code) and part 32-byte-record data tables. A SOFTWARE-ONLY break now looks plausible
and should be attempted before assuming a chip dump is mandatory.
